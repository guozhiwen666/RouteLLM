# 项目说明（写给不懂代码的你）

## 一句话：这个项目在干嘛？

这个系统就像一家医院的 **智能导诊台**，或者快递公司的 **自动分拣机**。

很多公司调用 AI 大模型时，不管问题难不难，都花钱请"最贵的专家"（云端最强模型）来回答。一顿操作猛如虎，月底账单两千五——其实 70% 的问题只是"帮我翻译一下""把这段话改成正式语气""把这堆东西分类"，请专家纯属浪费。

这个项目做的事就是：**把简单问题分给便宜的小模型（自家电脑上跑，几乎不要钱），只有真正难的问题才升级到贵的大模型**，并且全程盯着质量——省了钱，但不许质量塌方。

打个比方：
- **小模型（本地）** = 社区诊所的医生，看感冒发烧又快又便宜；
- **中模型（本地）** = 综合医院医生，看稍复杂一点的病；
- **大模型（云端，最贵）** = 顶尖专家，只有疑难杂症才请他；
- **这个系统** = 导诊台 + 病历本 + 质检员 + 记账员。

## 一次请求进来，发生了什么？

用大白话走一遍全流程（对应代码里的 6 个"办事窗口"）：

1. **接单员（查问题）**：先检查这条提问是不是"干净"的——有没有夹带别人的手机号、身份证号等隐私？是不是在问"现在股价多少"这种必须实时查的问题？并估一下这个问题有多长。

2. **翻老答案本（语义缓存）**：把问题和以前回答过的问题比对。如果几乎一模一样（相似度 ≥ 95%），而且关键信息对得上（问的是北京，绝不能拿上海的答案糊弄），就直接把旧答案抄给用户——**成本几乎为零**。但如果涉及隐私、涉及实时数据，坚决不抄旧答案。系统还带"版本意识"：换了新模型，旧答案本整体作废，绝不拿老模型的旧账糊弄新用户。

3. **导诊分流（路由决策）**——这是全系统的大脑，按顺序做四件事：
   - 先看"红灯清单"：这题沾了数学计算、写代码、超长文章、实时数据、要求严格格式？→ 直接送顶尖专家（因为小模型在 4-bit 压缩后做这些特别容易翻车，这是被实际数据打脸的教训）；
   - 再看是不是"明摆着的简单活"（很短、而且就是翻译/改写/分类这类）→ 直接送社区诊所；
   - 拿不准的，先问"值班的小医生"：这题你自己答得了吗？小医生诚实打分（置信度）；
   - 分数低于 0.75 的，一律"保守升级"送专家——**宁可多花钱，不许答错**。

4. **小诊所看病（小模型作答）**：社区医生开完方子，还不能直接发出去，系统要先"体检"这份答案：是不是在道歉敷衍（"很抱歉我无法回答"）？是不是卡壳复读（同一句话来回说）？答得太短？说要给 JSON 却给了一堆废话？**体检不过，马上换专家重新答一次**（只给一次机会，防止两家医院互相踢皮球）。

5. **专家作答（云端模型）**：专家也不是神仙，他那边网络可能抖动、账号可能限流，所以系统给专家配了"备用线路"和"重试机制"，一家挂了自动切下一家。

6. **收尾三件套（记答案、记账、抽查）**：
   - 答案如果质量过关、不涉隐私，就抄进"老答案本"，下次同样的问题直接命中；
   - 记账员按"读了多少字、写了多少字、缓存命中了多少"分别计价（云端按字数收钱，本地则按占用了多少时间的显卡折旧算），每笔请求的延迟也记录在案；
   - 质检员从每 100 条里抽 5 条，在后台偷偷让专家也答一遍，找个公正的"评审员"打分对比：如果小医生最近连续答得比专家差太多，系统会自动把门槛调高（更多问题送专家），差到离谱就**一键全切专家**，等人工排查。门槛只会自动抬高、不会自动放松——放松属于人的决定。

最后一步还有"保安"兜底：所有环节报错都不允许让用户直接看到崩溃，而是记录在案、走保守路线。

## 系统最怕什么？怎么防？

| 最怕的事 | 例子 | 对策 |
| --- | --- | --- |
| 简单问题答错（用户还不知道） | 把数学题交给被压缩坏的小模型 | 三层保险：置信度不够就升级 + 红灯清单强制升级 + 答案体检 |
| 缓存污染 | 问"上海限行"，返回"北京限行"的旧答案 | 相似度必须 ≥95% 且关键地名/时间/金额等必须完全一致才敢命中 |
| 隐私泄漏 | A 用户的私人问题被当成缓存答案给了 B 用户 | 含手机号/身份证/邮箱的请求绝不进缓存，也尽量不出内网 |
| 换了模型用户还看到旧答案 | 升级了模型，缓存里还是旧模型的答案 | 缓存按"模型版本"归档，换版本即作废 |
| 省钱省到质量塌了却没人发现 | 成本降了 87%，点踩率悄悄涨了 | 5% 抽查 + 自动升门槛 + 告警 |
| 小模型自己崩了 | 卡死、复读、道歉 | 答案体检不过就升级重试 |

## 目录是干什么的？（每类文件一句话）

- **config/**：系统的"设置清单"——有哪些模型档位、各档价格、阈值是多少。改参数改这里，不用动代码。
- **flow/state.py**：所有办事窗口共用的"交接单"（只放大家都要用的字段）。
- **flow/node/**：6 个"办事窗口"（上面流程的 1～6 步），每个窗口自己的小纸条（私有字段）写在自己文件顶部，不堆到交接单里。
- **utils/**：工具箱——怎么估算字数、怎么查隐私、怎么建向量、怎么重试网络请求、怎么给答案打分、怎么记账。谁都能调用，避免各窗口各写一套。
- **flow/engine.py + flow/graph.py**：流水线本身。engine 是"传送带"的机械原理，graph 是把 6 个窗口按顺序接起来（含"条件跳转"，比如体检不过就送去专家那里）。
- **main.py**：演示入口——没有真实模型也能跑，用"假医生"把整条流水线走一遍给你看。
- **tests/**：质检流水线自己的测试题（54 道），每次改动后跑一遍确认没改坏。

## 怎么跑起来看效果？

在项目根目录执行（需要 Python 3.14+）：

```
python main.py                          # 跑 7 条演示请求，看每条的"分诊结果"
python -m unittest discover -s tests    # 跑 54 道自检题
```

没有配置任何真实模型时，程序会用内置的"假医生"演示完整流程——你能清楚看到：同一句话第二次问命中缓存（档位显示 cache）、数学/代码类请求被红灯送去专家（frontier）、普通改写留在本地小模型（slm_tiny）等。

## 提醒

- 视频里的"假医生"是为了演示；真要省钱得接真实模型：本地部署 vLLM（给小模型用），云端配好 API Key（`MODEL_URL`、`OPENAI_API_BASE`、`OPENAI_API_KEY`）。
- config/routing.yaml 里的云端价格是占位数字，上线前必须改成真实报价，否则成本报表是自我安慰。
- 系统自带的是"简化版老答案本"（存在内存里、只能本机用），多台服务器一起跑时，需要换成共享的 Redis 版本（代码接口已留好）。
